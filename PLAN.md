# heimdash Plan

## Current Progress

- Single Zig executable with stdlib-only backend.
- Assets under `assets/` are embedded; there are no runtime asset paths.
- JSON config is generated by the NixOS module and is the Nix-to-Zig contract.
- Metrics render with configurable CPU, memory, disk, and per-disk thresholds.
- Service cards render links plus generic reachability from `url` or `check`.
- Service summaries render for `sonarr`, `radarr`, and `prowlarr`.
- `/poll` and `/poll/services` return `text/event-stream` Datastar patches.
- Service entries accept optional `kind` and `credential` metadata.
- Credentials are provided through systemd `LoadCredential` and resolved from `$CREDENTIALS_DIRECTORY`.
- Generated JSON contains credential names only, never credential source paths or values.
- Missing credential material leaves summaries blank and does not affect reachability.

## Remaining Gaps

- Summary adapters for Jellyfin, AdGuard, qBittorrent, and Home Assistant remain.
- Rendering still mixes metric IO and HTML emission.
- There is no long-lived SSE stream.

## Priority 1: Service Summary Adapter Expansion

### Scope

- Add compact read-only summaries for the remaining supported service kinds.
- Keep summary availability separate from reachability.
- Keep rendered cards to status, name, link, and one summary line.
- Do not add write endpoints, control buttons, persistence, or server auth.

### Order

| Order | Kind             | Auth          | Summary                         |
| ----- | ---------------- | ------------- | ------------------------------- |
| 2     | `jellyfin`       | API key token | version plus active sessions    |
| 3     | `adguard`        | HTTP Basic    | protection plus query stats     |
| 4     | `qbittorrent`    | cookie login  | version plus transfer speed     |
| 5     | `home_assistant` | Bearer token  | API status plus one entity line |

### Implementation

- Reuse the summary value types and `kind` dispatcher.
- Keep HTTP request code thin.
- Put new response parsing in pure helpers with fixture tests.
- Treat auth failures, missing credentials, network errors, and malformed JSON as summary unavailable.
- Never log, render, persist, or expose credential values.

### Validation

- `zig build test`
- `zig build`
- Fixture tests for parser success, missing fields, malformed JSON, and auth failure handling.
- Local smoke for `/poll/services?datastar=%7B%7D`.
- Confirm generated JSON, rendered HTML, logs, and process args contain no credential values.

## Priority 2: Render Purity Refactor

### Scope

- Separate metric gathering from metric rendering.
- Keep side effects at the edges: `/proc`, hostname, uptime, `statfs`, sockets, and HTTP.
- Preserve current routes, morph target IDs, and CSS hooks.

### Implementation

- Move metric value structs and render helpers out of IO-heavy `src/main.zig`.
- Give service-card and metric-row rendering focused unit coverage.
- Add any new pure module to the `build.zig` test target list.

### Validation

- `zig build test`
- `zig build`
- Request `/`, `/poll`, and `/poll/services` with a local config.
- Verify Datastar morph targets are unchanged.

## Priority 3: Long-Lived SSE

### Scope

- Add `GET /stream`.
- Keep `/poll` and `/poll/services` as compatibility and debugging endpoints.
- Reuse pure render helpers from Priority 2.

### Behavior

- Emit metrics every 30 seconds.
- Emit service reachability and summaries every 60 seconds.
- Emit comment heartbeat every 15 seconds.
- Close cleanly on client disconnect.
- Do not retain per-tick allocations.

### Validation

- `zig build test`
- `zig build`
- `curl -N http://127.0.0.1:<port>/stream`
- Browser idle test for 30 minutes.
- Repeated connect/disconnect cycles do not grow memory.
- Pull-mode endpoints still work.

## Out of Scope

- Service start, stop, or restart.
- Torrent actions.
- Home Assistant service calls.
- Auth in the Zig server.
- TLS in the Zig server.
- Prometheus export.
- Persistence.
- Log browser.
- Third-party Zig libraries.
- Separate frontend process.
- Host-specific service defaults or examples.
